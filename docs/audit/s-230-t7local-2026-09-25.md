### Root cause and observed state

The last original Maestro run, `~/.maestro/tests/2026-09-25_165433`, shows a
native **Unable to load script** red screen, not the Expo launcher or login.
Its Android log records:

```text
16:54:38.945 START ... VIEW dubbridge://expo-development-client/... MainActivity
16:54:39.669 The packager does not seem to be running ... Failed to connect to /10.0.2.2:8081
```

At investigation start, nothing listened on host `8081`, host `/status`
failed, and `adb reverse --list` already contained `tcp:8081 tcp:8081`.
`dumpsys activity activities` showed `.MainActivity` foreground. Opening the
loopback dev-client link with `am start -W` returned `Status: ok` and explicitly
reported delivery to the existing `.MainActivity`; it did not load a bundle.

`expo-dev-client`/`expo-dev-launcher` are absent from package dependencies,
installed node modules and the built APK's defined DEX packages. The APK was
installed at 16:51:12, before the failing run. The app scheme's VIEW intent
filter routes to `.MainActivity`, with no Dev Launcher URL interpreter. The
observed runtime is an Expo-modules React Native debug build. Expo's terminology
also distinguishes a debug build from one that includes the development-client
library: [Expo local app development](https://docs.expo.dev/guides/local-app-development/).

Installed React Native source confirms `AndroidInfoHelpers` selects
`10.0.2.2` for this emulator when `metro.host` is empty; `PackagerConnectionSettings`
also supports a stored debug-host override. Clearing state removes app data,
including authentication and any stored debug-host override, but cannot remove
a remembered Dev Launcher project from a library this APK does not contain.
No additional launcher initialization was needed to reach login after clearing.
