Dos rieles, un solo gate

El riel de infraestructura (S-230) y el riel de producto (MVP0-P2P) avanzan por sus propios gates y recién se tocan en dos puntos: P2.C0 congela los contratos que T6p-a consume, y todo converge en T9g, el único GO/NO-GO real de octubre. Dentro del riel de producto conviven dos ramas que no se tocan entre sí: el dispatch/ reconciliación/auditoría de backend (P2.T4–T6) y el P2P de mobile de cara al usuario. El gate que importa para seguir desarrollando ya no es el PASS agregado de P5: es P3 PASS → P4 PASS → P5-DEV → P6 PASS. P5.T3 queda como rama de certificación tardía y se reincorpora antes del veredicto P7/T9g. S-230-T7local, en el riel S-230, continúa como lane independiente y sigue siendo el smoke del base-flow S-230 contra el gateway Docker local; no es certificación P2P.

riel de infraestructura (S-230) riel de producto (MVP0-P2P) cadena de despliegue / gate compartido trabajo restante, sin empezar

T6p-a depende de T7local PASS + T7c PASS + DEV-HANDOFF + un freshness check de la evidencia T7local contra el head exacto de DEV-HANDOFF (84ea5edc, fijado 2026-09-25). Si cambiaron superficies relevantes del base flow, se corre una regresión acotada antes de T6p-a. El DEV-HANDOFF es exactamente P3 PASS + P4 PASS + P5-DEV + P6 PASS. P5-DEV significa P5.T0–T2 formalmente cerrados; no incluye P5.T3. P5.T3 conserva toda su fuerza como certificación física de release, pero ya no bloquea dashboard ni preparación de despliegue. Debe quedar PASS usando evidencia compatible de T7p o, a más tardar, en P7.T2. P7.T3 y T9g no pueden emitir PASS/GO si P5.T3 queda pendiente o falla.

Alcance del go-live

En alcance

Lo que el go-live sí demuestra
  • S-230Pipeline completo: login, upload, rights, HLS, ASR, subtítulos, revisión, publicación, reproducción
  • P2PUn dueño publica; un espectador invitado sincroniza y reproduce vía Hyperdrive/Hyperswarm cifrado

Condicional / doble-gate

Necesita que ambos rieles cierren
  • P2PReclamo de reproducción invitada — depende de T6p-d + P3–P6 + T7p + P7
  • S-230El GO de T9g exige CI verde, rollback ensayado y soak sin hallazgos bloqueantes

Fuera de alcance — ningún escenario

  • Doblaje con audio nuevo (S-150 T4–T7) — bloqueado por consentimiento ADR-028
  • iOS — el runtime P2P solo está probado en Android
  • Fallback HTTP/S3 para pasar la certificación P2P

Fix + 2 tests obsoletos corregidos, RRI 25 Low, revisión gpt-oss:20b PASS 0 hallazgos, owner-verified.
